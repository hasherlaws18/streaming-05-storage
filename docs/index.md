## Custom Project

### Dataset

I used the `sales.csv` dataset.

It contains sales transaction records.

Each record includes customer, product, pricing, and payment information.

### Kafka Messages

The producer reads records from `sales.csv`.

It sends each record to a Kafka topic.

I used `region_id` as the message key.

The original message fields were not changed.

### Consumer Processing

The consumer receives sales messages from Kafka.

It validates the data before processing.

It calculates `subtotal`, `tax_amount`, and `total`.

The consumer logs running statistics.

It writes processed records to `consumed_sales-Asher.csv`.

### Experiments

I added logic to detect a new lowest sale.

The consumer logs a **NEW LOWEST SALE** message when a lower sale total is found.

I also added a `new_lowest_sale` field to the output CSV.

### Results

The producer successfully streamed sales records through Kafka.

The consumer processed each message and calculated totals.

New lowest sales were detected and logged.

The processed records were saved to the output CSV file.

### Interpretation

This project showed how Kafka processes data in real time.

I learned how messages move from a producer to a consumer through a Kafka topic.

The stream can help a business monitor sales activity as transactions occur.

The consumed messages provided insights into sales totals, trends, and unusual transactions.
